# 结构

这个仓库现在只保留底层设施、工具层和桌面宿主；旧 UI 已移出仓库，新 UI 待接入。

## 三层关系

```text
工具层        shard/
                ↕  通过 server/tools 的工具网关接入
中间层        server/ + modules/
                ↕  HTTP /api/contract
UI 层         当前为空，新 UI 做好后接在这里

桌面宿主      electron-ipc/（不属于三层业务，只负责窗口、IPC、启动中间层）
```

`server/` 不认识具体 UI，`appDir` 指向哪里就提供哪里的静态页；UI 缺失时 API 仍然可用。

## 根目录

| 文件夹 | 职责 | 什么时候进这里 |
|---|---|---|
| `shard/` | 工具层：pi 扩展、skills、共享库、工具/项目清单 | 新增或修改 Agent 可用的工具、Skill、节点信息 |
| `server/` | 中间层基础设施：注册器、Agent 清单、状态存储、工具网关、单人启动、HTTP 契约 | 修改启动流程、API 契约、块组装、持久化 |
| `modules/` | 中间层领域块：agents、artifacts、flow、pi、runtime | 修改某个业务领域的规则、路由、生命周期 |
| `shared/` | 跨层共用：i18n、Markdown、pi 启动参数、Agent 清单校验 | 只有多个层都要用的纯工具或契约才放这里 |
| `electron-ipc/` | 桌面宿主：窗口、IPC、运行环境检查、安装编排 | 修改桌面入口、窗口行为、系统能力、运行时安装 |
| `scripts/` | 安装、卸载、安装器界面、开发检查、打包辅助 | 修改安装流程、卸载清理、测试入口、离线包下载 |
| `agents/` | Agent 项目模板，每个 `GEO_*` 是一个项目 | 新增或调整 Agent 的 `.pi` 配置、提示词、技能 |
| `presets/` | 默认流程预设 | 修改首次安装生成的默认流程 |
| `resources/` | 打包资源：图标、离线依赖、内置 Blender | 修改安装包图标或内置运行时 |
| `tests/` | 测试：目前只有服务端与公共测试辅助 | 新增服务端/契约/注册机制测试 |
| `workspace/` | 运行产物占位目录 | 由运行时写入，不手工放源码 |
| `data/` | 本地开发状态与启动日志 | 运行时生成，属于本机数据，不入库 |
| `node_modules/` | 依赖安装目录 | 由 npm 生成，不手工修改 |

## 各文件夹内部

### `shard/`

| 子文件夹 | 职责 |
|---|---|
| `extensions/` | pi 的工具扩展，按工具名登记到 shard 的清单 |
| `skills/` | Blender/Python 侧的技能、节点信息、共享脚本 |
| `lib/` | 扩展共用的运行库 |

工具层只通过 `server/tools` 的网关进入中间层；第二层不直接 import 这里的实现。

### `server/`

| 子文件夹 | 职责 |
|---|---|
| `kernel/` | 块注册与启动校验：重复 id、缺依赖、缺方法、循环依赖都会启动失败 |
| `registry/` | Agent 清单读取/校验、项目路径解析、Agent 对账、预设播种 |
| `store/` | 状态加载、保存、路径和通用错误类型 |
| `tools/` | 工具网关：只对外提供 `resolve` / `catalog` |
| `single/` | 单人模式的启动入口和路径解析 |

`server/` 根目录放 HTTP 契约、API 入口、块组装和开发服务器；这些是第二层的组合根，不属于某个领域块。

### `modules/`

每个子文件夹是一个领域块，自带对外接口和内部实现：

| 子文件夹 | 职责 |
|---|---|
| `agents/` | Agent 注册、会话生命周期、会话正文读取 |
| `artifacts/` | 运行目录准备、输入复制、产物收集、受限文件读取 |
| `flow/` | 流程的增删改查、旧数据迁移 |
| `pi/` | pi RPC 客户端：进程、事件、会话、中止、健康检查 |
| `runtime/` | 一次节点运行：会话选择、启动 pi、日志、转录、产物收集 |

块之间只通过声明好的 api 互相调用，不允许直接 import 另一个块的内部实现。

### `scripts/`

| 子文件夹 | 职责 |
|---|---|
| `setup/` | 安装逻辑：Node、pi、Git、Python、Blender、配置等卡片 |
| `setup-ui/` | 安装器界面：安装页、预览页、preload、安装页文案 |
| `installer/` | NSIS 安装包脚本，主要是卸载钩子和语言处理 |
| `dev/` | 开发检查：语法检查、测试入口 |
| `build/` | 打包辅助：离线依赖下载校验、构建产物清理 |

安装/卸载入口留在 `scripts/` 根目录，具体逻辑在子文件夹。

### `shared/`

跨层共用的纯代码：

- 服务端和桌面宿主共用的文案/国际化
- 会话正文的 Markdown 渲染
- pi RPC 和单人模式共用的启动参数
- 工具层和中间层共用的 Agent 清单校验

它不是领域块，也不是运行时服务；没有状态和生命周期。

### `electron-ipc/`

桌面宿主，不是三层业务的一部分：

- 主窗口的创建和启动顺序
- 渲染进程与主进程之间的 IPC
- 运行环境检查、安装流程编排、运行时路径
- 主窗口图标

它只调用中间层入口，不直接写业务流程。

### `tests/`

目前只保留服务端测试：

- `tests/server/`：契约、HTTP、注册、RPC、运行时、安装/卸载文案
- `tests/fixtures/`：测试替身
- 根目录的测试辅助：路径解析、临时目录、等待工具

新 UI 做好并放回 `app/` 后，UI 测试再回到 `tests/ui/`。

## 新增东西时先看哪个文件夹

| 要加的东西 | 先看 |
|---|---|
| 新工具 / 新 Skill | `shard/` |
| 新 API 端点 / 新业务规则 | `server/`（API 与组合根）+ `modules/<domain>/` |
| 新块或跨块依赖 | `server/`（块组装）+ 各领域块目录 |
| Agent 注册、路径、清单 | `server/registry/` + `shard/` |
| 安装步骤 / 卸载清理 | `scripts/setup/` + `scripts/installer/` |
| 安装器界面 | `scripts/setup-ui/` |
| 桌面窗口 / 系统 IPC | `electron-ipc/` |
| 多层共用的纯工具 | `shared/` |
| 测试入口 | `scripts/dev/` + `tests/server/` |
