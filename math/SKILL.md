# Math-First 数学先行

## 总路线（每次任务必须走，不许跳步）

1. **想方法**：把任务抽象成纯数学建模，列出**所有候选方法**（禁止想节点）。
2. **最小验证**：每个候选方法先跑最小数值实验（bpy 工具），拿初步数据。
3. **判定**：用「验证基准」（见下）逐条判定数据对不对。
4. **不对就换路**：记录「为什么不行」（证据 + 原因），换下一个候选方法，**禁止硬凑/微调参数假装对了**。
5. **选定路线**：把选中的方法做完整推演 → 结果落盘 `result.json`（见「落盘规范」）。

> 踩过坑的方法要记下来，避免后期节点阶段重踩。

## 阶段一：纯数学推演（禁止想节点）

- 只能用 bpy 工具环境里已装的库（trimesh / manifold3d / pyvista / numpy / scipy），**禁止** import bpy（Blender API）、禁止任何节点/Blender 界面术语。
- 写脚本时把"要算什么"拆成纯数值问题：输入是什么、输出想要什么。
- 用 bpy 工具跑脚本：expr 参数直接传 Python 代码（多行/中文均可），无需自己指定 Python 路径。


## 落盘规范（每次推演完必写，落盘即成果）

统一落盘到工程目录下 `<任务名>_math/` 文件夹，文件固定叫 `result.json`，结构：

```json
{
  "result":  {核心数据：数值结果表（每项可复核）},
  "explain": "白话解释：做了什么、得到什么、意味着什么",
  "routes":  {"可行": "选中的方法 + 为什么它是对的",
              "不可行": ["试过的方法1 + 失败证据 + 原因", "试过的方法2 + ..."]},
  "formulas": ["选定路线上的核心公式（如切割面方程、刀数-块数规律）"],
  "verify":  {"体积守恒": "数值", "外表面面积": "数值 vs 真值",
              "恒等式": "数值", "语义采样": "违例数", "交叉验证": "误差量级"}
}
```
- `routes` / `formulas` / `verify` 三节是给**后期节点阶段**的交接单：节点实现必须复用 `formulas`，验证节点输出参考 `verify`，`routes` 防止节点阶段重走不可行的路。

## 硬规则
- 数学结果不明确前，不许进入节点阶段。
- 所有脚本统一通过 bpy 工具（expr 参数）执行。
